# anti-workslop — Codex

먼저 프로젝트 루트의 `AGENTS.md`와 `.claude/skills/anti-workslop/SKILL.md`를 읽고 해당 모드의 절차를 따른다. 이 파일은 Codex 진입점이며 실행 구현은 기존 스킬을 공유한다.

## 경로

이 파일에서 세 단계 위가 프로젝트 루트다. 명령은 루트에서 실행한다. 본체 문서의 `references/`, `scripts/`, `tests/`는 `.claude/skills/anti-workslop/` 기준이다. `.agents/skills/`로 치환하지 않는다.

## Codex 도구 대응

- 본체의 `Agent`는 현재 세션의 서브에이전트 도구에 대응한다. 윤문·검토 모드에서 담당 하나를 만들고 모드·프로젝트 루트·원문 경로·확장자·가이드 이름·장르·전달 파일 경로를 넘긴다. 윤문은 탐지·전면 재작성·자기 대조까지, 검토는 탐지까지 맡긴다. 위험 신호나 의미 보존 의문이 있으면 본체 Step 3-1에 따라 독립 의미 검토 담당을 추가한다. 재작성 담당과 문맥을 공유하지 않고 원문·결과·위험 위치·불변식만 전달한다.
- 본체의 `SendMessage`는 같은 담당에 후속 작업을 보내는 동작이다. 이 환경에서 `collaboration.followup_task`가 제공되면 완료·대기 중인 담당을 다시 실행할 때 사용한다. `collaboration.send_message`는 실행 중인 담당에만 사용한다. 메시지만 전달하고 완료된 담당이 다시 실행되었다고 가정하지 않는다. 다른 환경에서는 재실행 기능이 있는 대응 도구를 사용한다.
- 검수 FAIL 시 마지막 판정 줄과 막는 항목 전체를 같은 담당에 전달한다. 수정과 자기 대조, 작업 기록 갱신이 끝난 뒤 `check_all`을 다시 실행한다. 최초 위임과 후속 수정은 같은 담당을 사용하며 최대 두 바퀴 제한은 본체를 따른다.
- 후속 실행 도구가 없으면 본 컨텍스트가 지적된 줄 언저리만 고치고, 바뀐 줄의 의미·규칙을 다시 대조하며 작업 기록도 갱신한다. notes에는 최초 진단 경로와 본 컨텍스트가 수행한 후속 수정을 구분해 적는다.
- 서브에이전트 도구가 없거나 현재 세션에서 위임이 허용되지 않으면 본체 Step 2의 직접 실행 경로를 따른다. 이 경우에만 본 컨텍스트가 원문과 `--bundle` 출력을 읽고 처리하며 notes의 진단 경로에 `본 컨텍스트`를 적는다.
- `Read`·`Write`·`Edit`는 Codex의 파일 읽기·쓰기·부분 수정 도구로 수행한다. `cat ... >> ...`는 PowerShell의 UTF-8 읽기·추가 쓰기 또는 Python으로 수행한다. 한국어가 깨지는 기본 인코딩을 쓰지 않는다.
- 스크래치패드는 세션에서 쓰기 가능한 임시 폴더를 사용한다. 서로 다른 실행의 전달 파일을 덮어쓰지 않는다.
- 본체의 마지막 발행 단계는 `.agents/skills/taste-builder/SKILL.md`의 도구 가용성 지침을 따른다. 발행 없이도 윤문과 검수는 완료할 수 있다.

원본 보존, 네 모드 구분, 검사 기준, 수정 최대 두 바퀴, 결과와 notes 형식은 본체와 같다. 검토 요청에는 고친 문장을 제공하지 않는다.
