# anti-workslop — Codex

먼저 프로젝트 루트의 `AGENTS.md`와 `.claude/skills/anti-workslop/SKILL.md`를 읽고 해당 모드의 절차를 따른다. 이 파일은 Codex 진입점이며 실행 구현은 기존 스킬을 공유한다.

## 경로

이 파일에서 세 단계 위가 프로젝트 루트다. 명령은 루트에서 실행한다. 본체 문서의 `references/`, `scripts/`, `tests/`는 `.claude/skills/anti-workslop/` 기준이다. `.agents/skills/`로 치환하지 않는다.

## Codex 도구 대응

- 본체의 `Agent`는 현재 세션의 서브에이전트 도구에 대응한다. 윤문·검토 모드에서 담당 하나를 만든다. 윤문은 본체 Step 2 대로 `check_all.py --prompt --record` 출력과 `references/writer.md` 를 담당에게 넘기고, 검토는 Step 2-1 대로 `--bundle` 로 탐지까지 맡긴다. 넘기는 값은 본체 각 Step 에 적힌 대로다.
- `check_all --hint` 출력의 `가이드:` 줄과 `사전 검사:` 줄은 본체 Step 1대로 읽는다. `가이드: 묻는다`면 사용자에게 묻는다.
- 윤문 담당은 검수를 직접 한 번 돌려 FAIL 이면 한 번 고친다. 본 컨텍스트의 검수는 확인만 하고 되돌리지 않는다. 되돌림은 본체대로 한 번이다.
- 서브에이전트 도구가 없거나 현재 세션에서 위임이 허용되지 않으면 윤문은 본 컨텍스트가 `--prompt` 출력대로, 검토는 `--bundle` 출력대로 직접 한다. 이 경우에만 본 컨텍스트가 원문을 읽고 처리하며 notes의 진단 경로에 `본 컨텍스트`를 적는다.
- `Read`·`Write`·`Edit`는 Codex의 파일 읽기·쓰기·부분 수정 도구로 수행한다. `cat ... >> ...`는 PowerShell의 UTF-8 읽기·추가 쓰기 또는 Python으로 수행한다. 한국어가 깨지는 기본 인코딩을 쓰지 않는다.
- 스크래치패드는 세션에서 쓰기 가능한 임시 폴더를 사용한다. 서로 다른 실행의 전달 파일을 덮어쓰지 않는다.
- 본체의 마지막 발행 단계는 `.agents/skills/taste-builder/SKILL.md`의 도구 가용성 지침을 따른다. 발행 없이도 윤문과 검수는 완료할 수 있다.

원본 보존, 네 모드 구분, 검사 기준, 되돌림 한 번, 결과와 notes 형식은 본체와 같다. 검토 요청에는 고친 문장을 제공하지 않는다.
