# 정성 통독 요령

정량 통계는 스크립트가 낸다. 통독은 **예문을 고르고 구조를 판단하는 일**이다. 새 숫자를 만들지 않는다.

## 읽는 순서

1. `stats.md`를 먼저 훑는다. 접속부사·종결어미·표기 변이·어휘 빈도 표가 무엇을 찾아야 하는지 알려 준다.
2. `reading-pack.md` Part A(글별 요약)를 전부 읽는다. 첫 문단·끝 문단·표제·리듬 후보가 있다.
3. 전독 대상 글을 `corpus/posts/<slug>.md`에서 읽는다. 20편 이하면 전부, 초과면 pack 머리에 적힌 전독 목록(최초 4·최근 4·최장 4).
4. Part B 후보 목록에서 슬롯별 예문을 고른다. **원문 그대로** 옮긴다. 줄임은 `…`로만 하고 단어를 바꾸지 않는다.
5. 워크시트를 채운다. `post_structure` 표부터 채우면 §6-1 편수가 자동으로 나온다.
6. `profile_proposals`에 topic_words·lexicon_report·spelling_pairs·banned 제안을 적고 profile.json에 반영한 뒤 analyze → derive를 다시 돌린다(한 번이면 된다).

## 슬롯별로 찾는 것

| 슬롯 | 어디서 | 판단 기준 |
|---|---|---|
| post_structure 도입 | Part A 첫 문단 | 저자 이력·경험·근황·실제 대화로 열면 **이력·경험**, 물음표면 **질문**, "X는 ~입니다"나 시대 배경이면 **정의·배경**, "저는 ~라고 생각합니다"로 시작하면 **결론·주장** |
| voice_* | 전체 인상 | 화자 위치(직접 해본 사람인가, 관찰자인가), 독자(누구에게 권하는가), 격식(합쇼체/해요체/반말), 목적(권유/기록/설득) |
| short_roles | B1 | 짧은 문장이 무슨 일을 하는가: 자문, 단정, 확인·안심, 전환, 추임새. 코퍼스에 있는 역할만 |
| rhythm_examples | Part A "짧은 문장이 낀 문단" | 짧은 문장 앞뒤에서 설명이 쌓이다 확인·강조로 떨어지는 문단 |
| conj_role_table | stats 접속부사 빈도 | 같은 역할의 접속어 중 빈도 순으로 "앞이 기본". 0회인 접속어는 "쓰지 않는 말" |
| paren_uses | B2 | 영문 병기 / 예시 / 사족·반응 / 주석 중 관찰된 것만 |
| haeyo_examples | B7 + stats 종결 세부 | 세부 어미별 1개. 어미가 관찰되지 않으면 줄을 만들지 않는다 |
| opening_examples_* | Part A 첫 문단 | 유형별 1~2개. 없는 유형은 "(관찰되지 않음)" |
| closing_examples | Part A 끝 문단·꼬리 | 권유·전망·감사·회고 중 실제로 쓰인 것 |
| lexicon_table | stats lexicon + 전독 | 첫 세 줄은 주제 어휘. 강조 부사·완화어·구어는 관찰된 것만 |
| contrast_pairs | B3 | 명사쌍만. "뿐만 아니라"는 대조가 아니다 |
| example_methods | B4·B5·전독 | 예시가 어떻게 들어오는가: 고유명사 나열, 괄호, 내 숫자, 비유, 인용, 가상 시나리오, 정리 목록. 없는 방식은 항목을 만들지 않는다 |
| conversion_examples | 전독 | '후' 칸은 저자 원문 문장을 그대로 쓰는 편이 안전하다. 새로 쓰면 counts 규칙(check_style --subset counts)을 통과해야 한다 |

## 하지 말 것

- **부재를 금지로 바꾸지 않는다.** 감각어가 0회인 것은 소재 효과일 수 있다. 템플릿의 금지 목록은 targets 등급을 따르고, 워크시트에서는 "관찰되지 않음"으로 적는다.
- **숫자를 손으로 적지 않는다.** 필요한 숫자는 `{{n:KEY}}`, `{{one_in:KEY}}`, `{{t:METRIC.rec}}`, `{{rhythm:slug:pN}}` 슬롯으로 넣는다. verify ②가 재렌더 동일성으로 잡아낸다.
- **예문을 다듬지 않는다.** 원문의 오탈자·띄어쓰기도 그대로. verify ⑥이 코퍼스와 대조한다.
- **원문에 없는 기능을 역할 목록에 넣지 않는다.** 예: 저자가 '-죠'를 거의 안 쓰면 haeyo_examples에 '-죠' 줄을 만들지 않는다.
- 완성본(`*_가이드라인.md`)을 직접 고치지 않는다. 고칠 것은 워크시트·profile·템플릿뿐이다.

## 20편 초과 코퍼스: 서브에이전트 분할

- `extract_reading_pack.py`가 `reading-pack.batch-K.md`를 만든다. 배치 하나와 워크시트 템플릿을 서브에이전트에 주고, **인용이 필요한 슬롯만**(short_roles, paren_uses, haeyo_examples, opening_examples_*, closing_examples, contrast_pairs, example_methods, emotion_examples, gloss_examples) 후보를 받아온다.
- 서브에이전트 지시에 반드시 넣을 것: "원문 그대로 인용", "숫자 쓰지 말 것", "[slug pN] 표시 유지", "없으면 '(관찰되지 않음)'".
- 메인 에이전트가 병합한다: 같은 인용 중복 제거, 슬롯당 상한(예문 3~4개), `post_structure`·`voice_*`·`body_order`·§9·§14 슬롯은 메인이 직접 쓴다.
- 어떤 인용을 고르는지는 실행마다 달라질 수 있다. 결정성은 숫자·구조·인용 존재 여부에만 보장된다.
