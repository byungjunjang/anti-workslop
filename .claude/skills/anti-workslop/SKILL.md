# anti-workslop

원칙(`principles/`)·스타일가이드(`styleguides/`)·취향(`taste/`) 세 레이어를 읽어 적용만 하는 스킬이다. 원칙은 `principles/ai-tells-ko.md` §5 절차로 손으로 더하고, 스타일가이드는 styleguide-builder 가, 취향은 taste-builder 가 만든다. 모드는 넷이고 사용자의 말이 모드를 정한다. 탐지·재작성·자기 대조는 서브에이전트 하나가 하고, 본 컨텍스트는 가이드 선택·검수·notes 만 맡는다. 본 컨텍스트는 원문·가이드·규칙 파일·브리프·전달 파일을 읽지 않는다.

## 공통

- 프로젝트 루트 = 이 SKILL.md 에서 세 단계 위(`.claude/skills/anti-workslop/` → 루트). 스크립트·데이터 경로는 루트 기준 상대 경로로 쓰고 절대 경로를 박지 않는다.
- 세 레이어 · 원칙은 누구에게나 AI 티인 것(`principles/ai-tells-ko.md`)과 고칠 때 깨지 않는 것(`principles/invariants.md`). 스타일가이드(기본 가이드라인)는 한 저자 또는 한 장르의 문체이고 `references/base-guidelines.json` 이 가리킨다. 취향은 이 사용자가 싫어하고 좋아하는 것(`taste/writing-taste.md`)이고 모든 문서에 댄다. 규칙의 「적용: …」은 그 규칙이 나온 장르다.
- 우선권 · 사용자 지시 > 불변식 > 취향 [규칙]·[경향] > 스타일가이드 hard > 취향 [관찰] > 스타일가이드 soft > 원칙 AI 티 S1 > S2 > S3. 충돌은 같은 구간에 반대 방향 지시가 있고 상위 규칙이 그 예외를 명시할 때만 성립하며, 명시가 없으면 모두 적용한다. 원칙 S1 은 검수 통과 기준이라 반드시 고친다. 스타일가이드가 원칙을 덮는 예외 목록은 `principles/ai-tells-ko.md` §4 표다.
- 불변식 셋. 하나라도 지킬 수 없으면 고치지 않는 쪽을 고른다. 전문은 `principles/invariants.md`. 가이드 §10 의 편집 규칙은 이 윤문에서 불변식 셋이 대신한다.
  1. 새 사실 금지 · 숫자·고유명사·인용·출처·새 주장을 더하지 않는다. 원문 숫자로 한 산술도 새 사실이다. 연결 문장과 원문 용어의 풀이는 더할 수 있고 전부 작업 기록에 남는다.
  2. 고정 구역 보존 · 표·코드·각주·링크 문법·`<!-- style-exempt -->` 구역·인용문 안·템플릿 고정 구역은 그대로 둔다. 본문의 문단 순서·소제목·목록과 산문 사이의 전환은 재작성이 정한다.
  3. 의미 보존 · 부정·조건·시제·확정 수준·단위를 유지한다.
- 길이는 묶지 않는다. 글이 늘어도 되고 줄어도 된다.
- 규칙 안에서 고칠 수 없으면 원문을 그대로 두고 notes 첫 줄에 `<!-- anti-workslop: 규칙 안에서 고칠 수 없음 — 검수 절 참조 -->` 를 남긴다.

## 모드

| 모드 | 트리거 | 응답 | 서브에이전트 |
|---|---|---|---|
| 윤문 | 윤문·퇴고·다듬어·고쳐·바꿔·taste polish | `.taste.<확장자>` + notes 네 절 | 탐지 · 재작성 · 자기 대조 |
| 검토 | 검토·검사·감사·짚어줘·「AI 티 검사만」 | 발견 목록만(다섯 칸·세 계층) | 탐지까지 |
| 구조 진단 | 「결론이 어디」·「두괄식인지」·「개요 상자」 | 진단표 네 칸 | 없음(가이드의 개요 상자 절만 읽는다) |
| 제안 후 대기 | 초안만·「이거 어때」·「한번 봐줘」 | 두 문장(증상 하나 + 질문 하나) | 없음 |

재작성본이나 고친 문장이 응답에 들어 있으면 검토가 아니다. 모드별 응답 형식과 예시는 `references/modes.md` 에 있다.

## Step 1. 입력과 스타일가이드

파일 경로 또는 텍스트를 받는다. 텍스트로 오면 세션 스크래치패드에 `<이름>.md` 로 저장하고 그 경로를 원문으로 쓴다. 어느 가이드로 고칠지는 **글의 종류**로 정하되 원문을 읽지 않고 힌트를 본다.

```text
python -X utf8 .claude/skills/anti-workslop/scripts/check_all.py --guide 없음 --hint <원문>
```

| 힌트 | 판단 신호 | 스타일가이드 |
|---|---|---|
| 줄글 | 산문 문장이 셋 이상 이어지고 명사형 종결 항목은 문장의 1/4 이하 | 줄글 가이드 |
| 개조식 | 항목이 셋 이상, 60% 이상이 '-함/-음/-필요/명사'로 끝나고 산문 문장보다 많다 | 개조식 가이드 |

힌트 둘째 줄은 장르별 등록 가이드와 취향 상태다. 그 장르에 「(기본)」 표시 없는 가이드가 하나면 그것, 둘 이상이면 묻고, 없으면 기본을 쓴다. `--base` 가 있으면 그것을 따른다. 첫 줄에 「<가이드>로 판단 · 힌트 한 줄」로 밝힌다. **애매하면 추측하지 않고 사용자에게 묻는다.** 힌트가 애매일 때(섞였거나 신호가 약함)와 이전에 다른 가이드로 편집된 판을 다시 받았을 때다. 질문은 한 번이고 선택지는 줄글 가이드 / 개조식 가이드 / 가이드 없이 취향만, 셋이다. 답을 `--base` 로 간주한다.

처음 쓰는 사람 · 쓴 장르가 기본 가이드뿐이면 styleguide-builder 로 내 글에서 가이드를 만들 수 있다고, 취향이 없음이거나 셋 다 0 이면 taste-builder 로 결과물에 「내가 쓴다면」 코멘트를 달아 취향을 쌓을 수 있다고 응답 끝에 한 문장씩 알린다. 대화마다 한 번이다.

`references/base-guidelines.json` 의 경로에 가이드 파일이 없으면 스타일가이드 없이 진행하고 밝힌다. 짧은 글은 줄글에만 있다. 공백 제외 800자 이하(`_short_chars`, 장피엠 §1-3)면 장르 검사기가 비율·불리언 규칙을 빼고 세며(`_checks_short`) 그 판정은 `check_all` 이 한다.

## Step 2. 서브에이전트 1회 (탐지 · 재작성 · 자기 대조)

`references/subagent.md` 를 브리프로 서브에이전트 하나를 부른다(Agent 도구, general-purpose, 모델 지정 없음). 채워 주는 값은 모드·프로젝트 루트·원문 경로·확장자·가이드 이름·장르·전달 파일 경로 일곱이다. 전달 파일은 세션 스크래치패드 아래 `diagnose/<원본명>.record.md`(윤문) 또는 `diagnose/<원본명>.findings.md`(검토)이고 프로젝트 안에는 두지 않는다. 호출 문장은 아래 한 줄이다.

```text
python -X utf8 .claude/skills/anti-workslop/scripts/check_all.py --guide 장피엠 --bundle <원문> 을 돌려 맨 앞의 브리프대로 한다. 모드 윤문, 프로젝트 루트 <루트>, 원문 <경로>, 확장자 md, 가이드 장피엠, 장르 줄글, 전달 파일 <스크래치 경로>.
```

서브에이전트는 원문과 `--bundle` 출력(브리프 · 읽기 묶음 · 검사기 셋의 진단)만 읽고, 사람 판단 규칙·가이드의 사람이 보는 항목·취향 전부를 원문에 대 본다. 윤문 모드면 글 전체를 가이드의 목소리와 취향으로 다시 쓰고 원문과 자기 대조해 `<원본명>.taste.<확장자>` 와 작업 기록(집계 · 고친 것 · 더한 것 · 뺀 것 · 작성자 확인)을 쓴다. 응답은 집계 한 줄 · 전달 파일 경로 · 작성자 확인 요약이다.

검토 모드는 응답에 실린 전달 파일(① 문장을 고칠 것 · ② 서식을 지울 것 · ③ 사람이 판단할 것 · 둘 것 · 충돌)에 `references/modes.md` 의 표시 규칙을 적용해 답하고 끝난다. 응답이 「고칠 것 0」이고 검사기 셋이 통과했으면 Step 5 조건 1 이다. Agent 도구가 없는 하네스에서는 본 컨텍스트가 같은 명령을 돌려 브리프대로 직접 한다.

## Step 3. 검수 (4단)

결과 파일에 `base-guidelines.json` 의 `_check_order` 순서로 돌린다.

| 순서 | 레이어 | 검사기 | 명령 | 통과 |
|---|---|---|---|---|
| 1 | 스타일가이드 | 장르 검사기 | `_checks[가이드][확장자]` (짧은 줄글은 `_checks_short`) | hard 0 |
| 2 | 원칙 | AI 티 | `_checks_common.ai_tells` (`{genre}` = `_genre_of[가이드]`) | S1 0, S2 finding 0 |
| 3 | 취향 | 검출 규칙 | `_checks_common.taste` | [규칙] 0. [경향]·[관찰] 은 보고만 |
| 4 | 불변식 | 대조 | `_checks_common.fidelity` (`check_fidelity`, `{orig}` = 원본 경로) | S1 0 (수치·인용·부정·자리표시자·링크·코드·표·각주. 표제·문단 수·길이는 보고만) |

넷은 `check_all.py --guide <가이드> --orig <원본> <결과>` 한 번으로 돌린다(`base-guidelines.json` 의 `_check_all`). 출력은 막는 항목과 판정 한 줄뿐이고, 어느 검사기의 전체 출력이 필요할 때만 표의 명령을 따로 돌린다. 사용자가 특정 취향 규칙을 빼라고 했을 때만 `--taste-skip W-NN` 을 붙인다.

FAIL 이면 본 컨텍스트가 결과 파일을 읽지 않는다. 판정 줄과 막는 항목을 `SendMessage` 로 같은 서브에이전트에 보내 고치게 하고 `check_all` 을 다시 돌린다. 최대 두 바퀴다. 남은 지적은 notes 미결에 적는다. 서브에이전트가 없는 하네스에서는 본 컨텍스트가 지적된 줄 언저리만 Read(offset·limit) 하고 Edit 한다.

## Step 4. notes

`<원본명>.taste-notes.md` 를 쓴다(원본은 건드리지 않는다). 네 절이고 앞의 셋만 본 컨텍스트가 쓴다. 작성자 확인·정본 교체는 `references/modes.md` 「윤문 뒤」를 따른다.

1. 작업 요약 · 서브에이전트 응답 세 줄 그대로.
2. 검수 · 첫 줄에 진단 경로(서브에이전트 / 본 컨텍스트). `check_all` 의 마지막 판정 줄 그대로, 바퀴 수, `--taste-skip` 한 W-NN 과 사용자 지시.
3. 미결 · 두 바퀴 뒤에도 남은 지적, 자리표시자.
4. 작업 기록 · 전달 파일을 셸로 덧붙인다(`cat <전달 파일> >> <notes>`). 뺀 것은 원문 그대로, 더한 것은 결과 그대로 인용되어 있다.

완성본에는 점수·수정 이유·작업 상태를 섞지 않는다. 검사기 전체 출력은 적지 않는다. 원본과 결과 파일로 언제든 다시 돌릴 수 있다.

## Step 5. 멱등성과 기권

`.taste.` 파일을 다시 받으면 재생성하지 않고 Step 3 검수만 한다. 이때 불변식 검사기의 원본은 같은 폴더의 `<원본명>.<확장자>` 이고, 없으면 그 검사만 건너뛰고 밝힌다. 조건 1·2·5·6·7에 걸리면 고치지 않고 `수정 없음: <이유>` 한 줄로 답한다. 3·4·8은 각 항목의 응답을 따른다.

1. 이미 깨끗함 · 서브에이전트 응답이 「고칠 것 0」이고 장르·원칙·취향 검사기 통과, human 취향 위반 0. 불변식 검사기는 결과물이 없어 해당 없음. 파일을 다시 저장하지 않는다.
2. `.taste.<확장자>` 재입력.
3. 짧은 글 · 줄글 공백 제외 800자 이하(Step 1). 비율 규칙은 검사기가 빼고 8문장 미만이면 문서 단위 S2 가 info 로 내려간다. 공지·메모·이메일이면 S1과 의미 보존 S1만 보고, 없으면 `수정 없음: 짧은 글, S1 없음`. 그 밖은 윤문한다.
4. 구조 진단 대상이 아님 · 회의결과·타임라인·절차서·런북·튜토리얼·감사·사과문. 시간순이 맞는 문서라고 한 줄로 밝히고 진단하지 않는다. 문장 윤문만 제안한다(modes.md 구조 진단).
5. 인용·전재 · 문서 전체가 인용이다.
6. 표·코드만 있는 문서.
7. 가이드 판단이 애매한데 사용자가 답하지 않음.
8. 제안을 거절함 · 같은 대화에서 다시 꺼내지 않는다.

## Step 6. 루프

결과를 다시 코멘트 받으려면 `taste-builder` 모드 A(publish)로 발행한다. `version` 은 `taste-v<취향 문서 버전>`. 코멘트가 쌓이면 taste-builder 모드 B 가 취향을 갱신하고 다음 윤문에 반영된다.
