# 서브에이전트 브리프 · 읽기, 전면 재작성, 자기 대조

anti-workslop 의 탐지와 재작성을 맡는다. 호출자(본 컨텍스트)는 원문을 읽지 않고 이 브리프도 읽지 않는다. `check_all.py --bundle` 출력의 맨 앞이 이 브리프이고, 그 뒤에 읽기 묶음과 진단이 이어진다. 호출 문장 예.

```text
python -X utf8 .claude/skills/anti-workslop/scripts/check_all.py --guide 장피엠 --bundle <원문> 을 돌려 맨 앞의 브리프대로 한다. 모드 윤문, 프로젝트 루트 <루트>, 원문 <경로>, 확장자 md, 가이드 장피엠, 장르 줄글, 전달 파일 <스크래치 경로>.
```

## 1. 순서

읽기 묶음의 보고서 장르 규칙 RT-01(`styleguides/report/title-claims.md`)을 확인한다. 원문을 읽고 대상 여부와 이유를 기록하며 문체 이름으로 장르를 정하지 않는다. 단계 2의 사람 판단에 제목 진단을 포함하므로 자동 검사 통과만으로 「고칠 것 0」을 선언하지 않는다. 윤문에서는 제목별 수정·유지·보호·미결 기록을 §2에, 검토에서는 고친 제목 없이 RT-01의 검토 기록 필드로 진단·근거만 §3의 ③과 둘 것·충돌에 남긴다. 자기 대조에는 확정 수준과 제목·첫 문장 반복 점검을 포함한다.

1. 원문을 Read 한다. `--bundle` 출력에서 읽기 묶음(가이드 §8·§11 사람이 보는 항목·§14 윤문 블록, 원칙 human 행과 §4, 취향 §0~§6)과 진단(장르·원칙·취향 검사기 finding, 첫 줄의 짧은 글 여부와 글자 수)을 읽는다. 진단은 「이런 것이 걸렸다」는 참고이지 편집 명세가 아니다. 가이드 §10 보존·멱등성 규칙과 §14 [작업]·[보존] 블록은 묶음에 없고, 이 윤문에서는 불변식 셋이 그 자리를 대신한다. 가이드 전문과 규칙 파일은 열지 않고 검사기 종료 코드는 보지 않는다.
2. 사람 판단. 원칙의 human 규칙 일곱(AT-24 권위 나열, AT-25 추정 메우기, AT-33 용어 변주, AT-60 설명 없는 은유·전문 은어, AT-61 이식 가능한 문장, AT-65 표지 없는 문단 끝 교훈, AT-66 세 가지 교훈형)은 묶음의 판정 질문으로, 가이드의 사람이 보는 항목(장피엠 §11-2, 개조식 §11-3) 전부와 취향 W-NN 전부(등급과 「적용: …」 불문)는 진술 그대로 원문에 대고 본다. 검사기 finding 과 합쳐 한 목록으로 만든다. 같은 자리에 둘 이상이 걸리면 우선권 체인(사용자 지시 > 불변식 > 취향 [규칙]·[경향] > 가이드 hard > 취향 [관찰] > 가이드 soft > 원칙 S1 > S2 > S3)의 상위만 남기고, `ai-tells-ko.md` §4 표에 해당하면 「§4 로 둔 것」에 근거 행과 함께 적는다. 임계 미만의 S2·S3 원시 매치는 넣지 않는다. 취향 문서가 비어 있으면 집계에 그 사실만 적는다. 검토 모드는 여기서 멈추고 §3 형식의 전달 파일을 쓰고 응답에 그 내용 전체를 싣는다.
3. 전면 재작성(윤문 모드). 목록이 비고 검사기 셋이 통과했으면 재작성하지 않고 응답에 「고칠 것 0」을 적고 RT-01 대상·유지 판단 기록도 전달 파일에 남긴다. 그 밖에는 가이드의 목소리와 취향으로 글 전체를 다시 쓴다. 자리를 땜질하지 않고 문단 단위로 다시 쓰며 문단 순서·병합·분할·소제목·목록과 산문 사이의 전환을 스스로 정한다. 고정 구역(표·코드·각주·링크 문법·`<!-- style-exempt -->` 구역·인용문 안·판정 상자 같은 템플릿 구역)은 그대로 둔다. 출처 없는 권위(AT-23·24)와 근거 없는 수치(AT-25)는 지우지 말고 `[근거 필요: …]` 를, 대상만의 사례가 없는 일반론(AT-61)은 `[사례 필요: …]` 를 남기며 귀속(「전문가들은」)도 떼지 않는다. 잠언·요약·훈계 마무리는 지우고 더 나은 교훈으로 갈지 않으며, 권유·전망으로 끝날 문장이 남지 않으면 `[마무리 필요: 권유·전망]` 을 남긴다. 용어 풀이는 첫 등장에 한 문장 이내. 짧은 글도 같은 순서다. 결과는 `<원본명>.taste.<확장자>` 로 쓰고 원문 파일은 그대로 둔다. 완성본에 점수·수정 이유·작업 상태를 섞지 않는다.
   - AT-66 은 같은 문형의 제목을 그 절 본문의 사실로 바꾸고 결론의 재나열과 개수 예고를 지우되, 부정·조건 표지나 수치가 든 제목은 고르지 않는다.
   - 불변식 셋 · 새 사실 금지(숫자·고유명사·인용·출처·새 주장, 원문 숫자로 한 산술 포함. 연결 문장과 원문 용어의 풀이는 허용) · 고정 구역 보존 · 의미 보존(부정·조건·시제·확정 수준·단위). 하나라도 지킬 수 없는 자리는 원문대로 두고 응답에 적는다. 전문은 `principles/invariants.md`.
   - 판정법 다섯 · S1 은 한 건으로 고치고 S2·S3 는 임계 이상만 · 접속부사는 지워도 뜻이 통하면 빼고 끊기면 앞 문단의 핵심어로 잇는다 · 「A가 아니라 B」는 부정이면 두고 확장·병렬이면 B 만 남긴다 · 평가어는 수치·사실로, 의인화는 주어를 사람·물건으로 갈아 보고, 광의 동사는 목적어를 갈아 본다 · 잠언·요약·훈계 마무리는 지운다.
4. 자기 대조. 원문과 결과를 나란히 놓고 넷을 한다. (a) 숫자·이름·인용·부정·조건·확정 수준이 문장마다 같은지 보고 다르면 되돌린다. (b) 원문에 짝이 없는 결과 문장을 전부 뽑는다 = 더한 것. (c) 결과에 짝이 없는 원문 문장을 전부 뽑는다 = 뺀 것. (d) 결과의 바뀐 줄에 human 규칙·가이드 항목·취향을 다시 대고 걸리면 고친다.
5. 작업 기록을 §2 형식으로 전달 파일 경로에 쓴다. 응답은 세 줄 · 집계(작업 기록 첫 줄 그대로) · 전달 파일 경로 · 작성자 확인 요약(자리표시자 수, 확신이 낮았던 수정 수). 재작성본은 응답에 싣지 않는다.

검수 FAIL 을 받으면 판정 줄의 막는 항목만 고치고, 바뀐 줄에 단계 4 의 (a)(d) 를 다시 한 뒤 작업 기록의 해당 절을 고친다.

## 2. 작업 기록 형식 (윤문 모드)

```text
집계 · <가이드> 기준: 고친 것 N건 (취향 N · 가이드 N · 원칙 N · 사람 판단 N), 더한 문장 N, 뺀 문장 N, 자리표시자 N · 짧은 글 예/아니오 (공백 제외 N자 → N자)

## 고친 것
<규칙 ID> · <위치: 절 이름과 문단 또는 항목 번호> · <원문 인용 그대로, 40자까지> · <수정 방향, 명사구>

## 더한 것
<결과 인용 그대로> · <연결 / 용어 풀이 / 마무리>

## 뺀 것
<원문 인용 그대로> · <규칙 ID 또는 이유>

## 작성자 확인
<자리표시자 · 위치 · 무엇을 채워야 하는지>
<확신이 낮았던 수정 · 규칙 ID · 위치 · 원문 인용 · 어느 쪽으로 왜 갔는지>
<§4 로 둔 것 · 규칙 ID · 위치 · 근거 행>
<충돌 · 구간 · 이긴 규칙 · 진 규칙>

## 제목 판단 · RT-01
<대상 여부와 이유>
<위치 | 수정 전 제목 | 수정 후 제목 | 본문 근거 인용·위치 | 확정 수준 전후·부정·조건·수치 보존 | 첫 문장 반복 점검 | 수정/유지/보호/미결 이유·작성자 확인>
```

빈 절은 `(없음)`. 고친 것에는 상한이 없다. 규칙 ID 를 댈 수 없는 수정은 「더한 것」이나 「뺀 것」에 이유와 함께 적는다.

## 3. 전달 파일 형식 (검토 모드)

```text
집계 · <가이드> 기준: 취향 N건, 가이드 hard N건 / soft N건, 원칙 S1 N건 / S2 N건, 사람 판단 N건 · 짧은 글 예/아니오 (공백 제외 N자)

## 고칠 것
① 문장을 고칠 것
<규칙 ID> · <위치> · <원문 인용 그대로, 40자까지> · <수정 방향, 명사구> · <S1/S2/S3 · hard/soft · [규칙]/[경향]/[관찰]>
② 서식을 지울 것
…
③ 사람이 판단할 것
<규칙 ID> · <위치> · <원문 인용> · <무엇을 확인하거나 결정해야 하는지, 명사구> · [사람]

## 둘 것
<규칙 ID> · <위치> · <원문 인용> · <§4 근거 행>

## 충돌
<구간> · <이긴 규칙> · <진 규칙>
```

①·②에는 검사기 finding 가운데 자리가 특정되는 것, ③에는 사람 판단(단계 2 의 human 규칙·가이드 항목·human 취향)을 둔다. 검토는 고치지 않는 모드라 ③이 뜻을 가진다. 표시 규칙(같은 규칙 4건 이상이면 처음 3건과 총 건수)은 호출자가 응답을 만들 때 적용한다. ③의 규칙 ID는 `AT-24`·`AT-25`·`AT-33`·`AT-60`·`AT-61`·`AT-65`·`AT-66`, 가이드 `§11-2 <항목 첫 여섯 글자>`(개조식은 `§11-3 <항목 첫 여섯 글자>`), `W-NN`, 보고서 제목 `RT-01` 중 하나다.

## 4. 하지 않는 것

- 원문 파일을 고치지 않고, 점수를 매기지 않고, AI 가 썼는지 말하지 않는다.
- 숫자·고유명사·인용·출처·새 주장을 더하지 않는다. 더한 문장을 「더한 것」에서 빠뜨리지 않는다.
- 고정 구역과 인용 안을 고치지 않는다.
- 프로젝트 안에는 `<원본명>.taste.<확장자>` 밖의 어떤 파일도 만들거나 고치지 않는다. 전달 파일은 스크래치패드에 둔다.

쓰기는 원문 크기로 가른다. 1만 자 이하면 작업 기록·재작성본을 Write 한 번씩. 넘으면 절 단위로 나눠 이어 붙인다. 한 번에 3,000자 이하로 쓴다.
