# 서브에이전트 브리프 · 진단과 재작성

anti-workslop 의 탐지와 재작성을 맡는다. 호출자(본 컨텍스트)는 원문을 읽지 않고 이 브리프도 읽지 않는다. `check_all.py --bundle` 출력의 맨 앞이 이 브리프이고, 그 뒤에 읽기 묶음과 진단이 이어진다. 호출 문장 예.

```text
python -X utf8 .claude/skills/anti-workslop/scripts/check_all.py --guide 장피엠 --bundle <원문> 을 돌려 맨 앞의 브리프대로 한다. 모드 윤문, 프로젝트 루트 <루트>, 원문 <경로>, 확장자 md, 가이드 장피엠, 장르 줄글, 전달 파일 <스크래치 경로>.
```

## 1. 순서

1. 원문을 Read 한다. 검사기 finding 의 줄 번호는 이 파일 기준이다.
2. `--bundle` 출력에서 읽기 묶음(가이드 §8·§11 사람이 보는 항목·§14 윤문 블록, 원칙 human 행과 §4, 취향 §0~§6)과 진단(장르·원칙·취향 검사기 finding, 첫 줄의 짧은 글 여부와 글자 수)을 읽는다. 가이드 전문과 규칙 파일은 열지 않는다. 검사기 종료 코드는 보지 않는다. 의미 보존 검사기는 호출자가 돌린다.
3. 사람 판단. 원칙의 human 규칙 일곱(AT-24 권위 나열, AT-25 추정 메우기, AT-33 용어 변주, AT-60 설명 없는 은유·전문 은어, AT-61 이식 가능한 문장, AT-65 표지 없는 문단 끝 교훈, AT-66 세 가지 교훈형)은 묶음의 판정 질문으로 본다. 가이드의 사람이 보는 항목(장피엠 §11-2, 개조식 §11-3) 전부를 원문에 대고 본다. 취향은 검출이 `human` 인 W-NN 만 진술 그대로 대고 본다. 어느 쪽이든 「적용: …」 범위에 드는 문서일 때만 올린다. 취향 문서가 비어 있으면 집계에 그 사실만 적는다.
4. 통합. 검사기 finding 과 사람 판단을 한 목록으로 합친다. 같은 자리에 둘 이상이 걸리면 우선권 체인(사용자 지시 > 불변식 > 취향 [규칙]·[경향] > 가이드 hard > 취향 [관찰] > 가이드 soft > 원칙 S1 > S2 > S3)의 상위만 남기고 진 규칙을 「충돌」 절에 적는다. `ai-tells-ko.md` §4 표에 해당하면 「둘 것」으로 옮기고 근거 행을 적는다. 임계 미만의 S2·S3 원시 매치는 넣지 않는다. ①·②에는 검사기 finding 가운데 문단 또는 항목 번호로 자리가 특정되는 것만 둔다. 검사기가 센 취향 finding 은 ①에 두고 심각도 칸에 등급을 적는다. 사람 판단(단계 3 의 human 규칙·가이드 항목·human 취향)은 확신이 있어도 ③에만 둔다. 재작성이 ③을 손대지 않으므로 ①에 올리면 사람의 결정을 대신하게 된다. 가이드 자동 계측 표의 문서 전체 분포 항목(어체 비율·평균 문장 길이·문단당 문장·쉼표·접속부사 비율)은 ③에 위치 「문서 전체」, 수정 방향 「문서 전체 분포 · 어미 전환·병합·분할만」으로 적는다. 출처 불명 권위(AT-23)와 근거 없는 수치(AT-25)는 수정 방향을 「자리표시자 `[근거 필요: …]`」로 적는다. AT-66 은 위치 「문서 전체」, 수정 방향은 설명표의 조작 가운데 쓸 것만(예: 「1절 제목을 본문 사실로 · 결론 재나열 삭제」). 인용은 40자까지. 같은 규칙이 여러 자리면 위치를 한 칸에 모은다.
5. 전달 파일을 §2 형식으로 쓴다. 검토 모드는 여기서 멈추고 응답에 전달 파일 내용 전체를 싣는다. 윤문 모드라도 고칠 것이 비어 있고 검사기 셋이 통과하면 재작성하지 않고 응답에 「고칠 것 0」 만 적는다.
6. 재작성(윤문 모드). 읽을 것은 이미 있다. 고칠 것 목록의 자리만 고치고 규칙 ID(`W-NN`·가이드 절 번호·`AT-NN`)를 댈 수 있는 수정만 한다. HTML 은 산문 블록만 고치고 표 셀·태그·경로·코드는 둔다. `<!-- style-exempt -->` 구역과 따옴표 인용 안은 고치지 않는다. §14 [보존]·[작업] 블록을 따른다. 둘 것과 ③은 손대지 않는다. 예외 둘 · ③의 「문서 전체 분포」는 어미 전환·문장 병합·분할로만 맞추고 정보를 더하지 않는다. ③의 AT-66 은 전달 파일에 적은 조작만 한다(같은 문형의 제목 하나 이상을 그 절 본문의 사실로 바꾸되 부정·조건 표지나 수치가 든 제목은 고르지 않고 새 제목에 수치·이름을 옮기지 않는다 · 결론 재나열과 개수 예고 삭제 · 짧은 글의 번호 셋은 번호를, 굵은 도입 셋은 굵게를 떼어 앞뒤 관계로 잇기 · 절을 만들거나 지우거나 순서를 바꾸지 않는다). 출처 불명 권위와 근거 없는 수치는 지우지 말고 `[근거 필요: …]` 를 남기며 귀속(「전문가들은」)도 떼지 않는다. 통째 삭제는 수정 원칙이 「지운다」인 규칙(AT-07·14·16·17·38·39·45·46·63)과 잠언·요약·훈계 마무리에만 허용하고, 지운 뒤 더 나은 문장으로 바꾸지 않고 앞의 구체 문장으로 끝낸다. 권유·전망으로 끝날 문장이 남지 않으면 `[마무리 필요: 권유·전망]` 을 남긴다. 결과는 `<원본명>.taste.<확장자>` 로 쓰고 원문 파일은 그대로 둔다. 완성본에 점수·수정 이유·작업 상태를 섞지 않는다. 마치면 바뀐 줄에만 human 취향·③ 질문을 다시 대고, 걸리면 되돌려 적용 기록에 적는다.
   - 불변식 넷 · 새 사실 금지(숫자·이름·인용·링크·주장, 원문 숫자로 한 산술 포함) · 구조 보존(문단 순서·소제목 층위·목록 중첩·표·코드·링크 문법·각주) · 의미 보존(지적된 자리만, 부정·조건·시제·확정 수준·단위 유지) · 길이 예산(원문의 110% 이하). 하나라도 지킬 수 없는 자리는 원문대로 두고 응답에 적는다. 전문은 `principles/invariants.md`.
   - 판정법 다섯 · S1 은 한 건으로 고치고 S2·S3 는 임계 이상만 · 접속부사는 지워도 뜻이 통하면 빼고 끊기면 앞 문단의 핵심어로 잇는다 · 「A가 아니라 B」는 부정이면 두고 확장·병렬이면 B 만 남긴다 · 평가어는 수치·사실로, 의인화는 주어를 사람·물건으로 갈아 보고, 광의 동사는 목적어를 갈아 본다 · 잠언·요약·훈계 마무리는 지운다.
7. 응답. 세 줄 묶음이다. 집계 한 줄(전달 파일 첫 줄 그대로) · 전달 파일 경로 · 적용 기록(지운 문장은 원문 그대로 · 적용하지 않은 고칠 것과 이유 · 남긴 자리표시자 · 어미 치환으로 늘어난 길이). 재작성본은 응답에 싣지 않는다.

## 2. 전달 파일 형식

```text
집계 · <가이드> 기준: 취향 N건, 가이드 hard N건 / soft N건, 원칙 S1 N건 / S2 N건, 사람 판단 N건 · 짧은 글 예/아니오 (공백 제외 N자)

## 고칠 것
① 문장을 고칠 것
<규칙 ID> · <위치: 절 이름과 문단 또는 항목 번호> · <원문 인용 그대로, 40자까지> · <수정 방향, 명사구> · <S1/S2/S3 · hard/soft · [규칙]/[경향]/[관찰]>
② 서식을 지울 것
…
③ 사람이 판단할 것
<규칙 ID> · <위치> · <원문 인용> · <무엇을 확인하거나 결정해야 하는지, 명사구> · [사람]

## 둘 것
<규칙 ID> · <위치> · <원문 인용> · <§4 근거 행>

## 충돌
<구간> · <이긴 규칙> · <진 규칙>
```

고칠 것에는 상한이 없다. 검토 모드의 표시 규칙(같은 규칙 4건 이상이면 처음 3건과 총 건수)은 호출자가 응답을 만들 때 적용한다. 빈 절은 `(없음)`으로 둔다. ③의 규칙 ID는 `AT-24`·`AT-25`·`AT-33`·`AT-60`·`AT-61`·`AT-65`·`AT-66`, 가이드 `§11-2 <항목 첫 여섯 글자>`(개조식은 `§11-3 <항목 첫 여섯 글자>`), `W-NN` 중 하나다.

## 3. 하지 않는 것

- 전달 파일에 고친 문장을 쓰지 않는다. 수정 방향은 「잠언 삭제, 앞 문장으로 종료」처럼 명사구다.
- 규칙 ID를 댈 수 없는 지적을 만들지 않는다. 원문 인용은 그대로 복사하고 길면 40자에서 끊는다.
- 원문 파일을 고치지 않고, 점수를 매기지 않고, AI가 썼는지 말하지 않는다.
- 프로젝트 안에는 `<원본명>.taste.<확장자>` 밖의 어떤 파일도 만들거나 고치지 않는다. 전달 파일은 스크래치패드에 둔다.

쓰기는 원문 크기로 가른다. 1만 자 이하면 전달 파일·재작성본을 Write 한 번씩. 넘으면 원문을 `cp` 로 복사해 고칠 자리마다 Edit 하고 전달 파일은 절마다 덧붙인다. 한 번에 3,000자 이하로 쓴다.
