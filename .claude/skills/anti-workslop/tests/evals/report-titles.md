# RT-01 의미 회귀 평가

자동 테스트 `tests/test_report_titles.py`는 읽기 묶음 전달과 기존 불변식 탐지만 검증한다. 아래는 본문을 읽는 에이전트가 실제로 윤문·검토하여 판단할 항목이다. 정규식이나 제목 종결어미로 합격을 판정하지 않는다.

새 세션에서 `fixtures/report-titles/decision.md`와 `personal.md`를 세션 임시 폴더에 복사한다. 저장소 픽스처는 수정하지 않는다. `.agents/skills/anti-workslop/SKILL.md` 진입점과 `check_all.py --guide 장피엠 --bundle <원문>`으로 수행한다. decision은 의사결정 보고서, personal은 개인 일기다. decision의 별도 원문 복사본에는 검토만 요청한다.

| 사례 | 본문 기반 기대 판단 |
|---|---|
| 문서 제목·주제 소개형 소제목 | 개발사 유형별 수수료 인하·지원 패키지 비교라는 원문 권고를 드러냄 |
| 이미 적절한 현지화 지원 제목 | 유지, 첫 문장이 제목 반복인지 별도 점검 |
| 시범 적용 검토 | 인력 확보 조건과 가능 수준을 보존. 자동검사와 충돌하면 원제목 유지·미결 |
| 계약 방식 검토 | 결론을 생성하지 않고 작성자 확인 |
| 부정 포함 원제목 | 기존 불변식으로 보호, 변경 필요성은 작성자 확인 |
| 출처·검토 기록·부록 | 안내용 제목 유지 |
| style-exempt 제목 | 구역 전체 보존 |
| 개인 일기 | RT-01 제외, 보고서 주장형 제목 강제 없음 |
| 검토 모드 | 원제목·본문 근거·진단과 이유만, 수정 제목과 재작성본 없음 |

추가 경계 평가: 분석 보고서 본문이 “지원 요청 증가의 원인은 출시 일정 중첩일 가능성이 있습니다”라고만 하면 제목에도 가설 수준을 보존한다. 제안서의 조건부 권고도 같은 기준으로 평가한다. 조건·수치가 든 원제목은 내용을 더 선명히 만들 수 있어도 보호한다. 조건·수치를 새 제목에 옮긴 결과 기존 검사와 충돌하면 검사 기준을 낮추지 않는다.

기록에는 원문/결과/작업 기록, 자동 검수 판정, 에이전트의 의미 판단, 미결을 구분한다. 09-17 실행 증거(`docs/report-title-evaluation-2026-09-17/`)는 2026-09-22 파이프라인 재검토를 앞두고 지웠다. 커밋 671de40 에서 볼 수 있다. 이는 이번 기능 검증용 새 원고이며 기존 원고·완성본·학습 자료의 소급 수정이 아니다.
