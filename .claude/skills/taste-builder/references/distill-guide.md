# 코멘트 → 규칙 증류 요령

## 1. 케이스 읽기
- `status: 신규` 케이스만 대상. 코멘트 원문, 앵커 인용, 종류를 본다.
- `질문`은 규칙을 만들지 않는다. `--map --status 보류 --note "사용자에게 되물음"`으로 두고 브리핑에서 되묻는다.
- `미분류`는 코멘트 내용으로 종류를 추정해 `note`에 "분류: 지적(추정)"처럼 적는다. `kind`는 바꾸지 않는다.

## 2. 진술로 바꾸기
- 코멘트를 "무엇을 → 어떻게"의 한 줄 규칙으로 바꾼다. 감정어는 빼고 관찰 가능한 표현으로. "딱딱해요" → "판정문의 명사 종결을 서술형으로".
- `[고침]` 케이스는 전(anchor.quote) → 후(rewrite)를 예로 붙인다.
- `[좋]` 케이스는 "유지" 규칙이다. "짧은 판정문(10자 안팎)은 유지".
- 기본 가이드라인의 특정 규칙을 덮는 취향은 그 번호를 적는다: "장피엠 §5-1 해요체 하한은 리포트에서 미적용".
- 검출 방식을 정한다. 표현 하나면 `literal`, 형태가 여럿이면 `regex`, 빈도 취향이면 `density`, 읽어야 아는 것이면 `human`. 어휘와 literal 구분자(` · `)는 `principles/ai-tells-ko.md` 규칙표와 같다. anti-workslop 의 `check_taste.py`가 이 필드로 초고를 센다(regex·literal 은 매치마다, density 는 임계 이상일 때). `validate_taste.py`는 형식과 예 매치를 검증한다.

## 3. 기존 규칙과 대조
- 같은 취향이면 그 규칙의 근거에 케이스를 추가하고 n을 다시 계산한다.
- 반대 취향이면 근거에 `-T-NNNN`으로 추가하고 n을 줄인다. n이 0 이하가 되거나 찬반이 갈리면 `[보류]`로 §7에 옮기고 양쪽 케이스를 적는다.
- 새 취향이면 다음 `W-NN`으로 신설한다. ID는 재사용하지 않는다.

## 4. 등급
- n = Σ(케이스 가중치). `kind: 규칙` 2, 그 외 1, 반대 케이스는 음수.
- `[관찰]` n=1, `[경향]` n=2~3, `[규칙]` n≥4, `[보류]` 그 외 또는 찬반 갈림.

## 5. 적용 범위
- 「적용: …」은 출처 표시다. 근거 케이스의 `doc.genre` 를 적고, 둘 이상이면 공통으로 올린다. anti-workslop 은 모든 문서에 댄다.
- `doc.base_guideline`이 같으면 "적용: 장피엠 기반 문서"처럼 적을 수 있다.

## 6. 절 배치
| 절 | 넣는 것 |
|---|---|
| 0 | 우선순위·범위에 관한 규칙 (예: "카운슬 리포트는 개조식 판을 기본으로") |
| 1 | 화자·어조·격식 |
| 2 | 문장 길이·연결·리듬·대구 |
| 3 | 어휘·표기·약어·병기 |
| 4 | 개조식/서술형 선택, 리포트 양식, 표·목록 |
| 5 | 장르별 예외 (다른 절 규칙의 예외) |
| 6 | 하지 말 것 |
| 7 | 보류·모순 |

## 7. 쓰기 규칙
- 규칙 줄 형식: `W-NN [등급] 진술 — 적용: 범위 — 근거: T-…, -T-… (n=가중합) — 예: 전 → 후 — 검출: 방식 [n/단위] 패턴 — 갱신 YYYY-MM-DD`. `validate_taste.py`가 이 형식을 파싱하므로 구분자 ` — `와 `근거:`·`(n=…)`를 지키지 않으면 검증에 잡히지 않는다.
- 검출 필드는 `— 예: 전 → 후` 뒤, `— 갱신` 앞에 둔다. `검출: regex \`p\``, `검출: literal \`a · b\``, `검출: density n/문서|문단|문장 \`p\``, `검출: human`. 없으면 human이다. 예외 칸은 두지 않는다. 예외는 진술에 말로 적는다.
- `validate_taste.py`는 regex·literal·density의 패턴을 컴파일하고, `예`의 전에 1회 이상·후에 0회 매치를 요구한다(E10 방식 오류, E11 패턴 오류, E12 예 불일치). `예`가 `전 → 후` 자리표시자 그대로면 E12는 건너뛴다.
- 패턴은 백틱으로 감싼다. 패턴 안에 ` — `를 쓰지 않는다.
- 머리 줄의 케이스 수와 등급 집계를 본문과 맞춘다.
- 코멘트 원문이나 인용을 규칙 진술에 넣을 때는 큰따옴표로 감싼다.
- 문서에 검수 상태·작업 메모를 쓰지 않는다. 그런 것은 changelog에.
