# taste · 취향 레이어

anti-workslop 윤문의 세 레이어(원칙·스타일가이드·취향) 가운데 취향이다. 원칙은 누구에게나 같고 스타일가이드는 한 저자의 문체지만, 취향은 이 도구를 쓰는 사람 한 명의 것이다. 그래서 저장소에는 기본 취향이 없고 각자 빈 문서에서 시작한다.

## 시작

Claude Code 에서 「코멘트 달 수 있게 올려줘」라고 하면 taste-builder 가 이 폴더를 만들고 AI 결과물을 코멘트용 아티팩트로 올린다. 폴더만 먼저 만들려면 프로젝트 루트에서 아래 명령을 돌린다.

```text
python -X utf8 .claude/skills/taste-builder/scripts/init_taste.py
```

## 쌓는 법

1. AI 가 쓴 글을 올리고 claude.ai 에서 연다.
2. 걸리는 문장을 드래그해 「내가 쓴다면 이렇게 쓴다」를 코멘트로 단다. 고쳐 쓴 문장이 가장 좋은 재료다. 이유만 적어도 된다.
3. 「코멘트 반영해줘」라고 하면 코멘트가 케이스로 쌓이고, 같은 방향의 케이스가 모이면 규칙이 된다. 한 건이면 관찰, 두세 건이면 경향, 네 건부터 규칙이다. `[규칙]` 태그를 단 코멘트는 두 건으로 센다.
4. 다음 윤문부터 anti-workslop 이 그 규칙을 적용한다. 결과를 다시 올려 코멘트를 달면 취향이 더 선명해진다.

## 파일

| 파일 | 내용 |
|---|---|
| `writing-taste.md` | 취향 문서. 윤문이 읽는 규칙 |
| `cases/cases.jsonl` | 코멘트 원장. 추가만 한다 |
| `cases/raw/` | 수집할 때마다 남기는 코멘트 원본 |
| `changelog.md` | 갱신 기록 |
| `artifacts.json` | 올린 아티팩트 목록 |

이 폴더에는 내 코멘트와 원문 인용이 그대로 남는다. 고객 문서나 사내 문서를 올렸다면 공개 저장소에 푸시하지 않는다. 배포본 `.gitignore` 는 이 README 만 남기고 폴더를 막아 둔다. 비공개 저장소로 여러 PC 에서 동기화하려면 그 두 줄을 지운다.
